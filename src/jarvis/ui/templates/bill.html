The re-write tax — {{ bill_ui.money(bill.rewrite.list_usd) }} of the above

Not an extra charge — a part of the cache-write line, named. {{ fmt_tok(bill.rewrite.tokens) }} tokens of this order's context were sent to be cached MORE THAN ONCE, across {{ bill.rewrite.boundaries }} turn boundar{{ 'ies' if bill.rewrite.boundaries != 1 else 'y' }}.

Every turn is a separate claude --resume process. Claude Code puts git status in its system prompt, so a worker — whose job is editing files — presents a different prompt prefix on its next turn, the cached conversation is invalidated, and the whole of it is re-sent at the cache-WRITE rate (1.25–2×) instead of being served at the cache-READ rate (0.1×). The cause is upstream and Jarvis cannot fix it; what it can do is cost fewer boundaries, which is why sending a worker one message beats sending it three.
